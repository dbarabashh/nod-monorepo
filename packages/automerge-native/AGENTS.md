# Native Automerge (`packages/automerge-native`, `@nod/automerge-native`)

Runs `@automerge/automerge` where there is no WebAssembly (Hermes on iOS and
Android). Automerge's JS layer works over a swappable backend
(`Automerge.use(api)`). On desktop that backend is the wasm build the package
ships; on mobile it is this package: a JS shim over a Rust library built from
the same Automerge source, so both clients write identical bytes and
`@nod/core` runs unchanged.

## Layout

```
src/backend.ts        createBackend(): the api Automerge.use() takes
src/document/         NativeHandle, wasm's Automerge class: core.ts (lifecycle,
                      history), reads.ts (values, JS objects, patches),
                      handle.ts (writes)
src/client.ts         JSON requests to the native store; frees collected handles
src/protocol.ts       request types, mirroring rust/src/protocol.rs
src/materialize.ts    builds JS objects from a materialized tree, as wasm does
src/patches.ts        patches in wasm's shape
src/values/           JS value <-> typed JSON, ported from automerge-wasm's interop
src/testing/          compatibility scenarios and their fixtures (generated by
                      `pnpm fixtures`), and the Rust library as bare wasm for Node
src/react-native/     installNativeAutomerge(); diagnostics.ts runs the scenarios
                      on a device
metro.cjs             withNativeAutomerge(): maps the app to Automerge's slim
                      build and stubs its wasm glue
rust/                 the Rust library: JSON protocol, C ABI, Android JNI
ios/, android/        the Expo module wrapping the library
scripts/              build the library for wasm, iOS and Android (cargo.ts is
                      shared); write fixtures
```

## How it fits together

- The shim implements the backend methods Automerge's JS layer calls. Plain
  data operations go to Rust as one JSON request each (`nod_am_call`); JS
  objects are built in the shim the way automerge-wasm builds them.
- The Rust crate depends on `automerge` by git revision: the exact commit the
  JS package is built from (`js/automerge-<version>` tag). Both run the same
  code with UTF-16 text indexing, so documents match byte for byte.
- `installNativeAutomerge()` must run before any document is made; the mobile
  app calls it from `src/lib/automerge.ts`, imported first by the root layout.

## Known differences from wasm

The bytes, hashes, values and patches are the same. What differs:

- After a change, wasm patches the previous JS objects and shares unchanged
  ones between versions; this backend builds the document anew each time. So
  objects are never `===` across versions, and with `freeze: true` every
  object is frozen (wasm leaves the changed ones unfrozen). `@nod/core` relies
  on neither.
- Unsupported, and refused with an error: sync messages, `decodeChange` and
  so `getHistory(...)[i].change`, `hasHeads`, marks, blocks, cursors, authors,
  fragments and bundles.
- After a panic in Rust, every document is dropped and each call fails until
  the app restarts (wasm traps the same way). Storage code must treat that
  error as the backend failing, not as a corrupt file.
- Nesting is limited: requests deeper than serde_json's 128 levels and
  documents deeper than 256 are refused with an error rather than risking the
  native stack. Meetings nest four levels.
- Native documents are freed through `FinalizationRegistry`, which Hermes has
  (checked on iOS and Android); without it they would live until the app
  quits.

## Rules

- Keep the crate's `automerge` revision and the npm `@automerge/automerge`
  version in step. Changing either: update both, run
  `pnpm --filter @nod/automerge-native fixtures`, review the fixture diff, and
  run the tests. The fixture test fails if the wasm backend writes anything new,
  and the native tests fail if this backend writes anything different.
- Port behavior from automerge-wasm (`rust/automerge-wasm/src` at the pinned
  tag); never invent semantics. Its quirks are kept on purpose: bare numbers
  below 1 are stored as f64, uint values come out as BigInt.
- A backend method that isn't implemented throws "not supported by the native
  Automerge backend". Never return a guess.
- Tests run the core suite on this backend too, so `pnpm test` here needs Rust
  (`rustup`, the version in `rust/rust-toolchain.toml`). Building for iOS needs
  Xcode; for Android, the NDK with `ANDROID_HOME` set.
- The library is built, never committed: Gradle's `preBuild` builds it for the
  app's architectures (skipped while the Rust sources are unchanged), and
  `pod install` and `pnpm ios` run `scripts/build-ios.ts`, which rebuilds it
  whenever the sources differ from `source-stamp` in the XCFramework. After changing Rust, run
  `pnpm ios` (or `pod install`) before building from Xcode.
- On a device, the app's Diagnostics screen (dev builds) runs the same
  scenarios against the fixtures.
